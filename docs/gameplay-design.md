# Gameplay Design

The design record for how Mitts plays — mechanics, feel, and the reasoning
behind them. This is reference, not working context: read it when changing a
gameplay mechanic, not for every task.

Where the numbers actually live is listed at the end of this document.

## Core mechanics

**Mouse + keyboard and gamepad are both first-class; which one drives is pure last-input-wins** — there is **no opt-in flag and no mode switch**. `InputDeviceTracker` (autoload) tracks the CURRENTLY-driving device: touch the mouse and it drives, push the stick and the pad takes over, with switch thresholds set above the gameplay deadzones (`_STICK_SWITCH_DEADZONE` 0.5 vs. aim/move ~0.15) so a resting/drifting stick never steals control. `InputDeviceTracker.is_gamepad_active()` is the single source of truth every device-facing surface reads — so a mouse player who never touches a plugged-in pad is simply always KBM and sees zero gamepad UI, and a Steam Deck player just uses the pad and everything works, no setting to find. The one setting is an accessibility OFF switch (Options → Controls, "Keyboard/Mouse Only" → `PlayerPrefs.disable_gamepad`, off by default): it pins `is_gamepad_active()` false so a drifting/unwanted controller that can't be unplugged is ignored entirely (Options apply calls `InputDeviceTracker.notify_gate_changed()` so the flip reaches the device-aware UI without new input). **Control, prompts, and focus rings all stay linked** because they all key off that one flag:
- **Control**: `LocalInputGatherer._gamepad_active()` and the spectator free cam branch on `is_gamepad_active()`.
- **Prompt glyphs** (`ControllerGlyphs.prompt`): the persistent hints (the HUD menu-open + skip-vote prompts, the side-menu close hint) rebuild on `InputDeviceTracker.device_changed`, so pressing the mouse flips them to keyboard labels and pushing the stick flips them to pad glyphs; the **tutorial's teaching prose** does the same (`_pick` / `_build_key_tokens` read `is_gamepad_active()`, and it re-emits the current step on `device_changed`).
- **Menu focus rings**: the tracker owns ONE shared focus-ring stylebox (`InputDeviceTracker.focus_ring()`, handed out by `MenuStyle.apply_focus_ring` / `controller_focus_theme`) that goes teal while the pad drives and zero-width/invisible the instant the mouse does. So controls can be focusable unconditionally and a mouse click still shows no ring; `ControllerNav.active()` (which gates whether focus is *grabbed*) is `is_gamepad_active()`. `boot.gd` focuses Play at build so a pad player's first button press activates it, and the device-aware ring keeps that focus invisible for a mouse player.

Device *arbitration* is a purely local, presentation-time concern — which device drives decides how the local `InputState` gets *populated* (OS mouse vs. synthesized-from-stick), and no peer needs to know which one you used. That does **not** mean the pad path is netcode-free: the committed wrister power it produces is a real replicated input field (see the wrister bullet below), because a parked pad cursor gives the host nothing to re-derive power from. Treat "which device" as local and "what the device committed" as wire. WASD skates, mouse cursor places the blade in real-time (continuous IK — the blade chases the cursor every frame, no aim button). When the pad is the active device, `LocalInputGatherer` swaps the aim source: the right stick becomes an absolute "skill stick" (`GamepadAimRules`) that synthesizes a screen cursor into the same `InputState.mouse_screen_pos`/`mouse_world_pos` the mouse feeds, so blade IK runs unchanged (left stick skates, the pad's buttons map onto the existing action flags). Stickhandling maps the stick to an absolute blade offset (easing to a forward carry rest on release); the **wrister** is a *committed* shot rather than the mouse's flick — while RT is held the cursor parks in the stick direction **anchored on the puck, pinned at the trigger edge** (`_pin_shot_anchor` / `_shot_anchor_screen`, NOT the body and NOT a live blade read: the aim is positional origin→cursor from that same puck, so a body-anchored cursor made the shot line the stick direction *parallel-shifted by the ~1 m carry offset* — a ~4°–15° bias that flipped with carry side and rode the dynamic zoom — while a live blade anchor would swing the line as the skater carried the blade away from the pinned origin. Pinning at the edge makes stick direction = shot line by construction, at any zoom, for the whole hold — and it's what lets the swing-chirality hand read work on a pad) while **RT's own analog travel commits the power fraction** (`InputState.commit_wrister_power` → the same `bot_wrister_power_t` path bots use, *replacing* the cursor-speed read since a parked cursor has ~0 speed), so a controller shot is "point the stick, pull the trigger as hard as you want it, release to fire" with no flick timing. **Aim and power are on different digits on purpose** — they were both on the right stick (bearing *and* push magnitude), and a thumb cannot hold a bearing on a corner while metering a magnitude, so every precise shot cost the other axis; the trigger has travel of its own to spend. That makes the aim **hold on a centered stick** for free (a stick inside the deadzone carries no bearing, so the thumb coming home can't collapse a lined-up shot) and it means the power band is the trigger's *usable* travel: from the press point (`TRIGGER_PRESS`, XInput's low 30/255 button point — a high one would spend half the throw just arming the shot) up to `TRIGGER_FULL`, which stops short of the mechanical stop because pads differ in how close to 1.0 they actually report and a full rip must not live in travel some hardware can't produce. Since the shot fires on release and a trigger sweeps its whole travel on the way out, the latch **freezes while the trigger is springing back** (`GamepadAimRules.trigger_is_springing_back` — a return spring unloads at ~15-25 units/s, a deliberate ease-off at ~1-3, an order of magnitude apart), so the shot reads the power you were *holding*; easing off slowly still genuinely softens it. A pad with **digital shoulders** (Switch Pro and friends, where SDL maps ZR onto the trigger axis as a bare 0/1) lands on full travel at the press edge and holds it — every shot a full rip, the only honest reading of a trigger with nothing to meter. (`commit_wrister_power` + the power fraction are **on the wire** as of `PROTOCOL_VERSION` v41 — flag bit [13] plus a u8, so an online pad client's shot power reaches the host instead of the host re-deriving it from the parked cursor and firing a floater. The gatherer quantizes to the wire grid at the *source* (`InputState.quantize_power_t`) so local prediction and the host match bit-exactly.) Camera is third-person, per-player, dynamic-zoom, tilted ~75° so cursor-to-world projection stays usable for stickhandling.

**Stickhandling is physical, not abstract.** The puck is a real simulated disc that attaches to the blade by proximity; there is no possession flag you press to engage. Carrying slows you. Moving the cursor swings the blade through forehand/backhand with a small lift through center — that's the "dangling" texture. Hard incoming pucks (above `deflect_min_speed`, 22 m/s **receiver-relative**) deflect off a poorly-angled blade; passes (snap ~14, AI feeds solved to arrive at 20 m/s *in the receiver's frame* — `AIActionScoring.PASS_TARGET_CLOSING_M_S` — soft-sweep wristers down to ~10) catch at any angle for a static or retreating receiver. Reception is purely reactive — it reads the puck's speed **in the receiver's frame** (puck velocity − skater velocity) and the blade angle at contact, nothing else — so a stretch pass to a streaking receiver arrives soft (easy catch), charging head-on into the same feed steepens it past catchable, and skating backward with a hard shot cushions it under the ceiling ("give with the puck" as a *skating* read). Squaring the blade to the relative incoming line is what lets you corral a harder shot (the `alignment_receive_bonus` ceiling, 30 m/s relative); there is deliberately no blade-velocity cushion term (it rewarded a preemptive backswing that felt fiddly — the frame correction rewards positioning, not stick wind-up). The 22/30 thresholds are calibrated to real reception — pros routinely handle ~45–50 mph feeds and treat ~60+ mph as a knock-down even squared; force math + sources on `PuckReceptionRules.should_receive`. Above that ceiling the contact is a **deflect**, and the deflect physics itself produces the whole spectrum from a **bobble** (you knocked it down, it dies in front — a squared blade smothering a hard shot) to a **live redirect** (a glancing blade tips the puck off its line at near-full pace — the deflection-goal geometry). **Hold Q (Deflect) without the puck to deliberately deflect** — a committed "redirect this, don't catch it" that tips even an otherwise-catchable puck off the blade face (angle the blade with the cursor to aim the redirect); release to receive normally. The **loft level (scroll)** picks the deflection *intent* rather than a launch height (a monotonic "higher = launch higher" would rocket a hard tip over the net) — the four levels are **deflect modes** that name the redirect outright and set the blade's plane: **FLAT** keeps a grounded puck low (redirect along the ice); **LOW** takes a grounded puck **up** (the money tip — lift a low shot up and in); **MID** raises the blade to the low air (~0.35 m pivot) and tips an airborne puck **up** — roof the rising shot; **HIGH** raises it to the high air (~0.52 m pivot, reaching ~1.05 m — where net-front feeds arrive) and bats an airborne puck **down** (`PuckCollisionRules.deflect_loft_speed`) — the knockdown at the mouth. The direction is your stated intent, never a puck-vs-blade height read, so identical contacts never flip outcome on a centimeter. Camping an air mode can't cheese saucer passes, because a saucer apexes at ~0.21 — under even the MID pivot — so getting your blade under a puck means it's genuinely high. The raised HIGH blade is also what hooks under an opponent's shaft, so **stick-lift is the same gesture** (hold Q at HIGH near a carrier's stick). Reach follows the blade plane (FLAT/LOW play the ice, MID the low air, HIGH the high air); the level picks which plane you play and names the direction on it. Deliberate and natural deflects run the *same* physics (`PuckCollisionRules.deflect_velocity`), so they always feel identical — one **normal/tangential decomposition** of the incoming velocity against the blade face (the into-face component rebounds with a speed-dependent restitution so hard pucks die head-on; the along-face glance is kept, so a tip holds its pace), with bobble/redirect emerging from blade angle alone and the loft level signing the redirect (flat / up / down). Tunables (`deflect_*`, `bobble_*`) live on `Puck` (detail in ARCHITECTURE → Puck Interactions). AI bots don't use deliberate deflect or voluntary lift (their one-timers hold the slapshot charge off-puck — the real one-timer mechanic, wind-up and all); Q off-puck for a human is deflect, tapped-on-puck it's still the nudge. No `deke` button — deception is blade placement plus skating rhythm. **The blade plays the puck at a real contact point, and the contact is a push** (`docs/stickhandling-push-model-plan.md`). While carrying, the blade renders on the side of the puck it is pushing from — the side *opposite* the puck's motion in the carrier's frame (`CarryContactRules`, fed by blade velocity every peer derives from the replicated pose) — so dangling in place alternates faces per stroke, a slow pull-across keeps one face the whole way, and each face flip is a one-hop rise over the puck. Below the stroke threshold the blade cradles on its current side. **Inward pulls play a grammar forced by blade geometry**: no face points back at the carrier, so pulling the puck in requires hooking the toe over it — an inward pull on the forehand diagonal rolls the wrists closed and curls the toe in over the puck (the toe drag — also triggered positionally when the shaft steepens past its lie, `Skater.get_toe_drag_factor`), while a backhand-side pull cups mildly (the cradle — a backhand can't roll to a forehand hook). Each stroke has contact *prosody*, told by the blade sliding along its own heel→toe axis: a hard push rides the puck out toward the toe (the toe is the last point of contact of every real stroke, so releases leave off the toe by construction), the blade hangs over the top between touches (`carry_transit_hop_time`), and the far face lands heel-first and rolls the puck back to the seat. During a **wrister wind-up, the blade seats the frozen puck heel→toe per the loft level** (`Skater._aim_seat_offset_u` — FLAT at the heel, HIGH at the toe), so the level is not just a HUD chevron on your own screen but a *diegetic tell* a defender or goalie can read off a committed shooter's blade before the release — and the eased slide between rungs is exactly the deception window, since switching the level late beats a read that has already been made. Every one of these tells **moves the blade, never the puck**: the puck stays pinned exactly at the cursor, the storytelling rides the blade mesh, and releases still fire from mid-blade. The push side telegraphs the next stroke the same way — the blade winds up where it's about to push from, and a good dangler beats that read by changing late.

**Three fire inputs, all aim-aware** (the quick pass, plus two real shots):
- **Quick pass** (E, rebindable) — fires *instantly* from carry (no aim state), a fixed-power blade→cursor snap toward the cursor. This is the **pass**, not a viable shot — its power is flat pass speed for everyone. Aim is blade→cursor (from the puck's position toward the cursor, so it goes where you point); it deliberately does *not* aim player→blade, which used to inherit the blade's lateral carry-side offset and pull the pass off the cursor line. It's on its own button so there's no tap-vs-hold guess: originally the quick pass and wrister shared LMB and were split by a ~60 ms hold-time cutoff, but an ordinary tap that lingered a few ticks fired a wrister when the player wanted a snap pass. AI bots fire it via the `quick_pass_pressed` input flag (their uncharged pass). (Internally the button/action/flag are all `quick_pass*`; older history called it "quick shot" — it is a pass, treat it as one.)
- **Wrister** (LMB) — a **coil-and-release**: LMB-down FREEZES the blade+puck at the shot origin (the puck sits *still* where it'll fire from — a legible "committing to a shot" tell for the goalie and other players) while the torso **coils** toward the cursor — and the frozen blade **addresses the shot**: the visible blade slides over the still puck onto the trailing side of the live aim line (origin→cursor), the side it will push the shot from — the push model applied to the shot itself (`Skater.set_wrister_address` + the same `CarryContactRules.stroke_side` rule strokes use), so pulling back onto the backhand and then aiming a forehand re-addresses on the spot, and the wind-up pose tracks the aim geometrically (it cannot sit on the wrong side of the puck; mesh-only, so the pin, release origin, and aim line are untouched); releasing fires **instantly** along **origin→cursor** — the *positional* aim ("the puck fires from where it sits toward where you point"), the SAME aim the quick pass uses, so a quick pass is just a fixed-power wrister and the two no longer fight (the old drag-vector aim is gone — it conflicted with the quick pass and couldn't be previewed). The origin (`SkaterAimingBehavior.wrister_origin_world`) is pinned at charge start and reconcile-restored like the rest of the charge state. Power is unchanged: the **pure mouse-speed model** (`ShotMechanics.wrister_power_t`) — raw screen-space cursor speed at release, scaled by **Shot Power Sensitivity** (DPI-independent), feel-curve exponent (`wrister_power_curve`); slow sweep = soft touch pass (floor ~10 m/s), hard flick = ~33 m/s Shot-scaled ceiling. Forehand/backhand is the **cursor's bearing-sweep chirality** (`ShotMechanics.is_backhand_from_swing`; the blade is frozen, so the cursor is the only sweep — a straight drag defaults forehand via `wrister_backhand_deadband`). The clockwise check runs on the **shot line, origin→cursor** — the same vector the release fires along — **not** on a body-relative bearing: measured about the body it would also rotate with the ~1 m blade parallax, banking swing the player never gestured. (For a mouse the anchor also tracks the skater's translation since the pin — `ChargeTracking.swing_anchor` — because the cursor's *world* point rides the skater-following camera: about a purely world-pinned anchor, skating backwards dragged the cursor toward/past the origin and misread forehands as backhands. The pad's shot cursor is anchored on the pin itself, so it stays world-pinned; `commit_wrister_power` picks the frame on both ends of the wire.) That one anchor choice is what makes the read device-agnostic — a mouse sweeps the shot line by moving the cursor, a pad by rotating the stick (whose cursor is anchored on the puck, so stick bearing *is* the shot line's bearing) — so there is no per-device hand branch. The **blade-travel power gate is DORMANT** (`ShotMechanics.wrister_travel_cap_t`, `wrister_full_stroke_travel`): a frozen blade banks no blade path, so `_wrister_stroke_travel` returns INF and power is uncapped mouse-speed (twitch = max for now) — the mechanism is kept as the hook for a future **cursor-sweep** anti-degeneracy gate. `shot_charge` still carries normalized release-now power (the goalie's pre-lean + the stick-flex pose read it); no on-screen charge ring. **Release → follow-through is an explosive, arm-controlled "whip"** (`SkaterShotPoseCoordinator._apply_wrister_whip`): the blade drives forward *along the shot line from the body* (`ShotMechanics.whip_local_dir` keeps it on the shot vector as the torso rotates — never radial, and the arm can't stretch because it's the hand carry, not a blade anchor), on an **attack-hold-release** envelope (`wrister_whip_attack_frac`/`_release_frac`) so it snaps to the extended finish and holds; the torso **through-overshoot is direct-driven** (discharges *with* the release, no lerp lag that read as delay), facing **re-squares hard** through the finish (`follow_through_facing_recover_speed` — the coil freezes facing at the wind-up cursor, so without this the blade hands back to cursor-tracking by swinging to the stale-facing side), and the **legs kick** (`SkaterSkatingCoordinator`, powered by the actual release charge so a hard flick kicks hard). Tunables (`wrister_mouse_speed_full`, `wrister_mouse_speed_smoothing`, `wrister_power_curve`, `wrister_backhand_deadband`, `wrister_follow_through_*`, `wrister_whip_*`, `follow_through_*` incl. `follow_through_facing_recover_speed`) on `SkaterController`; `wrister_power_curve`'s default is shared with bots via `GameRules`. **Bots have no cursor, so they COMMIT their intent directly** (the same seam that already commits power): aim direction, hand, and power via `InputState.bot_wrister_aim_dir` / `bot_wrister_backhand` / `bot_wrister_power_t`, set in the agent's shoot/charged-pass states — the exact shot the scorer evaluated (`release_pos → aim_point`, execution error folded in). The controller uses the commits for bots (`_wrister_aim_dir` / `_wrister_is_backhand`) and positional/sweep for humans; the bot's synthesized cursor is now purely the cosmetic wind-up coil (it no longer drives aim or chirality). Real puck, real stickhandling, real physics — only the input layer is synthesized.
- **Slapshot** (RMB) — time-charged wind-up, aim locked at press. Charge feedback is **fully diegetic**: the wind-up animation (blade lift, torso coil, stick rising to `slapper_wind_up_height`) fills over the same `max_slapper_charge_time` as the charge itself — the pose IS the gauge — with a small blade quiver at the apex as the full-charge tell (`slapper_full_quiver_*`); there is no charge ring. Supports **one-timers**: charge without the puck, release fires when the puck enters the shooting zone, at whatever charge was actually built (plus the `one_timer_center_power_bonus` timing bonus) — winding up early is what buys a full-power one-timer. A one-timer does **not** leave on the button edge. Letting go commits the swing into a short **retention** hold (`one_timer_retention_time`, `SkaterStateMachine.ONE_TIMER_RETENTION`) — the blade holds its loaded pose, the shaft bows to full flex against the caught puck, and only then does the shot come off the recoil. That beat is the blade travelling down onto the puck, so it is sized to the slapper follow-through's own downswing: the puck now leaves on the frame the finish animation already treated as contact, rather than a tenth of a second before the stick gets there. The hold is **uncancellable** — you are committed the moment you let go, and a defender who pokes the puck off the blade inside it earns a whiff swung through empty air. Because the range check runs at the *end* of the hold, the leniency ring folds the retention's puck travel in (`one_timer_effective_leniency_time`), so the timing tolerance around the feed is unchanged — you simply see the catch. A **plain slapshot from carry** (no one-timer window armed) is untouched and still fires on the button edge. The locked aim is **blade→cursor** for humans; **bots commit the direction** (`InputState.bot_slapper_aim_dir`, the same seam as the wrister's `bot_wrister_aim_dir`) since they can't reconstruct the blade's world anchor from a snapshot — the one-timer is their only slapper, and it commits the settled release point → the scored net hole.

Backhand shots take a power penalty (which also, emergently, kills the backhand point snipe while leaving the in-tight backhand roof alive — arrival height rides pace). Scroll wheel steps a four-level **loft mode** (flat / low / mid / high) that applies to every charged release in every direction. Each level is a **set launch angle** from your blade curve's ladder (M88 7/15.5/21°, M92 8/17.5/24°, M28 8.5/19/28° — `ShotMechanics.shot_loft_y`), never a solve: charge buys pace, the level buys angle, and where the arc crosses the net is emergent from angle × charge × range — **including over the bar**. Missing high is the price of greed and learning your arcs is the sniping skill. At full wrister charge the top-shelf bands land roughly: LOW = the point snipe (M92 ~13–21 m), MID = the slot (~3–4 m), HIGH = the doorstep roof (~2–2.7 m, and from the true crease only the M28's 28° gets there — doorstep floors ~2.2/1.9/1.6 m by gear); easing the charge slides every band closer. The M88's flat ladder can never sail — a max slapper at LOW apexes at crossbar-ping height, iron at worst — but can't roof in tight; the M28 owns the doorstep and pays for it at range on every rung. Quick passes are the exception: the saucer (LOW) and flip (MID/HIGH) keep fixed vertical launch speeds (`loft_vertical_speed_*` on `SkaterController`), gear-free, so the passing game never reads your shot ladder. (Design of record: `docs/elevation-rework-plan.md` v3.)

**Skating is momentum-driven.** Thrust accelerates, drag-friction decelerates naturally, Space brakes hard (heavy friction, direction-agnostic). Backward and lateral (crossover) movement are slower than forward. Facing lazily tracks the cursor, and auto-freezes during shot aim/charge/block states and when the cursor swings into the unreachable wedge behind the skater. No frame-perfect inputs — reads and positioning matter more than execution precision.

**Sprint (Shift) is a stamina-gated top-speed burst.** Holding sprint while skating raises the speed cap (and bumps thrust to reach it) but *widens the turn radius* (`sprint_turn_multiplier` scales facing turn rate in `SkaterPoseCoordinator.apply_facing`) — committed straight-line speed traded for agility, so it's a read rather than a hold-always button. It drains a stamina pool; carrying the puck drains it faster. Empty the pool and sprint locks out until it regenerates past half. The gauge is a BOTW-style **stamina ring** nested inside the local player's own on-ice color ring (`SkaterHUDCoordinator`, self-only): hidden while full, amber when low, flashing red during the exhaustion lockout. Stamina is a 0..1 pool computed by `stamina_rules.gd` (pure/deterministic so it survives reconcile replay), replicated on `SkaterNetworkState` and snapped from the host at replay start like velocity. Tunables (`sprint_*`, `stamina_regen_per_sec`) live on `SkaterController`. Stamina is **Weight-flavored metabolism** (attributes v4 — the fork rides the frame dial, no other lever touches it): a lean player has a shallower pool (drains faster) but recovers fast, a heavy player a deep pool (drains slow) but slow recovery — lean = short repeatable bursts, heavy = one long drive then a slow refill. The sprint *ceiling* is speed-normalized and grounded to the 20–25 mph NHL burst band (`sprint_ceiling_mult`); body-only builds sit in a tight middle band and the skate-profile gear slot re-widens it (~20.5–24 mph) — see **Player Attributes → Sprint & carry**.

**Physicality is emergent, not scripted.** Body checks trigger from closing-velocity impulse, not a hit button. Ctrl drops into a shot block — the one-knee drop a real skater plays, stick-side knee down and the far leg extended along the ice, stick flat on the other side. The seal is that pose: wider than the torso (the extended leg and the stick cover the halves the body doesn't) and sealed from the ice up, but capped at the kneeling body's height — a committed blocker owns the ice and concedes the air. It is a BODY commitment and nothing else: the blade is choreographed flat across the lane and stops playing the puck entirely, so a blocker corrals nothing, pokes nobody, and lifts no sticks until he stands up. Poke-checks are stick-on-stick momentum contests — the blades collide and the puck goes where the blended momentum sends it. **Contested pickups** — two blades reaching the same loose puck (a faceoff draw or a board scramble) — are the same kind of contest: nobody is ever awarded possession, the puck squirts free *biased toward the stronger blade's momentum* (a true 50/50 pops out sideways, the "pinched seed"). One resolution, `PuckCollisionRules.contested_pickup_velocity`, shared by the host's present-time pickup tick and the networked lag-comp claim path, so scrambles feel identical however the contestants are hosted. Blade speed already reflects Hands, so the draw rewards the better dangler emergently — no attribute term.

**A hard check staggers its victim.** Beyond the knockback impulse, absorbing a check inflicts a temporary thrust penalty plus a stamina bite, both scaled by how hard it landed — the m/s transfer impulse, which already folds in attacker Size/Physical and the closing Speed, and victim mass. The math is pure (`Scripts/domain/rules/body_check_rules.gd`): hit strength normalizes to a 0..1 intensity between `stagger_min_impulse` and `stagger_ref_impulse`, and a single value, `stagger_timer` (seconds remaining), encodes **both** the penalty depth and the recovery window — a harder hit sets a longer timer, and the per-tick thrust penalty is proportional to the time left, so it eases back to full thrust on its own. The stamina bite charges only the stagger a hit adds *beyond* the residual (`incremental_stamina_drain`), so a clean hit bites full but grinding someone on the boards bleeds at ~the decay rate instead of emptying the pool tick-by-tick. The debuff is host-authoritative (victim-only `Skater.body_check_received` signal — distinct from the both-roles `body_check_impulse_applied`, so a delivered hit's restitution bounce never self-staggers the attacker) and replicated as `stagger_timer`, snapped and re-derived through reconcile exactly like stamina. Tunables (`stagger_*`) live on `SkaterController`; flat for all players in v1 (the hit strength already reflects the combatants' attributes). **Check feedback scales with hit strength too:** the burst (particle count + velocity) and impact sound (volume + pitch) read the same intensity in `SkaterVFX`, which owns one throttled code path for both — a short cosmetic de-dup window coalesces the per-tick re-fires of `body_checked_player` during sustained contact so one hit reads as one impact. (Genuine head-on collisions still emit from both bodies by design — two impact points.)

**Goalies are AI-only, never player-controlled.** Tuned for *beatable realism* — they should look and move like a real goalie while staying deliberately scorable (the realism additions only ever open scoring windows, never buff a set goalie into a brick wall). Reactive with a small reaction delay (the window for close-range top-corner goals) that a **pre-armed read** shortens when the goalie has been fixated on a visible windup (quiet-eye anticipation — a quick-release snap *from range* never earns the windup prime), and that an opposing carrier already **in the slot arms by proximity** (`prime_slot_distance`, set-and-sighted — a coiled goalie is never a frozen statue on a quick in-tight release; the prime only makes the limbs *start* moving, the reach-speed cap still bounds coverage so you beat him by picking a corner out of reach); positional depth chart on the challenge-angle arc, with a **speed-matched rush backflow** (a closing carrier retreats the goalie along the taught curve at the attacker's pace — decelerating strands him out at challenge depth); butterfly with a commit timer to prevent toggling and a **grounded ~0.2 s drop** (measured pro drop speed, so clean low shots in tight beat a purely reactive drop — sealing early via the proactive triggers is the counter); **squares to the puck, not the shooter's body** (dangle jitter is absorbed by distance-scaled tracking lag — the quiet-eye smoothing — rather than by aiming at the chest). The read degrades exactly when a real goalie's would: **screened** (a body in the puck→goalie sightline delays pickup, and a *fully* screened release flips save selection to a blocking butterfly — drop on the read, eat the top-corner exposure) and **caught moving / unset** (mid-push, sliding, or standing up reads the shot late). Lateral pushes **accelerate onto the edge** (`lateral_accel`) rather than snapping to speed, so quick cross-ice plays beat the goalie across; when the cross-crease race is *already lost* the goalie goes **pads-first** (drop-and-slide toward the crossing) instead of arriving late upright. Two anticipatory reads guard the back door: a live **weak-side one-timer man caps the challenge depth** (`backdoor_depth_cap` — a pass-flight vs. re-square race, so respecting the back door opens the carrier's direct-shot angle instead), and a lateral drive that **wins the race to the post** (`is_beaten_wide` — keyed on the *puck*, not the body: a forehand-drag drive with the puck trailing commits nothing until the puck crosses the goalie's sealing reach, the point of no return — and it must be a *sustained* drive — carrier-driven lateral commits hold for a quiet-eye confirmation beat, `lateral_commit_confirm_s`, so a deke's transient spike un-commits when pulled back; pass-driven seals stay instant since a puck in flight can't cut back) drops the goalie into the butterfly-slide post seal rather than an unwinnable standing chase — baiting that committed drop with a fake held past the confirmation is the counter. Post play splits at the goal line: **RVH** seals at/below it (wraps, walkouts, dead angles), **VH** — post pad vertical, body tall — takes the in-front sharp-angle shot threat, closing RVH's short-side-high hole. While down, the goalie **knee-shuffles** (slow sealed micro-scoots toward the arc target) between committed slides — the real three-tier down movement — and the **head tracks the raw puck** in every state (eyes-lead; the body plays the smoothed threat). A committed **stick lunge is a gamble** (fully-unset read while extended). Loose pucks in the crease follow the real cover-vs-clear hierarchy: the corner sweep is **lane-aware** (exit corner picked by opponent reach-vs-flight — `sweep_lane_blocked`; a covered lane flips corners), and when **every lane is covered with an opponent on the puck, the goalie smothers it** (`COVERING` — a glove-race cover that a well-timed whack still beats), and a puck that comes to **rest on the goalie's body** (a deadened save settling on the pad tops — the only body that can support a puck off the ice) triggers the same smother, since no blade can legally reach it there. The cover resolves by ruleset: `NHL` whistles the play dead and faces off in the defensive zone; `ARCADE`/`OFF` run a flow-preserving **hold-and-release** (~0.85 s of dead puck that kills the scramble and lets the defense reset, then the goalie plays it out himself through the same lane-aware sweep — no stoppage, the same philosophy as the offside ghost), spaced by a cover cooldown. Bots treat the covered puck as dead (the loose-puck chase election returns nobody while it's locked), so they reset to their slots instead of crowding the smother. The goalie also **plays rims behind the net** — tier-1 conservative only ("stop it, leave it, get back"): a paddle-down trap at the boards directly behind the cage, gated by an ultra-conservative go/no-go race (full-sprint forechecker assumption, whole-trip clock, fat margin, net-front lurker veto) and re-checked every tick with a stricter abort margin so he visibly bails early rather than ever getting caught out; he never carries or passes (the misplay-prone tiers of real puck handling are deliberately absent), the trip routes around the post via a waypoint — skated with a real stride (a procedural gait borrowed from the skater's stroke warp, distance-driven so it freezes when he stops; PLAYING_PUCK only, the crease glide is correct goaltending) — and only the HARD tier plays the puck at all (`GoalieSkillProfile.puck_play_go_margin_s` is INF below it). Saves follow real rebound doctrine: the chest **absorbs dead**, the glove **catches and holds** (squeeze-and-look — a catch under pressure freezes the play through the same rails as the smother, NHL whistle / ARCADE hold; an unpressured catch look-and-drops after a beat and plays on, the real delay-of-game incentive), controlled pad/blocker saves are **steered cornerward at pace** (modern active rebounds — `GoalieSaveRules`), hard shots beat the pad and kick a live rebound; angled pads (pose toe-out + pad material, not a physics override) keep deflections out of the slot. Pure read/positioning/rebound math lives in `Scripts/domain/rules/goalie_behavior_rules.gd`; tuning is `@export`s on `Scripts/controllers/goalie_controller.gd`.

**Game format:** 3v3 or 5v5 (the lobby's Mode row; `team_size` latches at puck drop exactly like the ruleset, and OT keeps the match's size), three periods plus optional OT, period length tunable. In 5v5 the lobby slot IS the position (LD/LW/C/RW/RD — `team_slot` 3/1/0/2/4): the AI's role layer branches at one seam (`TeamBrain` → `AIRoleSlots5`, a group-scoped election where D and F compete only for their group's jobs, cross-filling when a group runs short), the D-zone runs the researched hybrid zone (`zone_coverage.gd` + `zone_defense.gd`), points/line-holds/valve live in `defenseman.gd`, and the carrier's turnover price gains the 5v5-gated **transition-exposure** counter-rush term (`AIActionScoring.counter_rush_cost`). The 3v3 role path is untouched by construction. Faceoffs have a short "2 → 1 → DROP" prep; the drop is a **live** puck (no possession assignment), so winning the draw is a real contested pickup — see *Physicality* above — decided by which center's blade wins the momentum contest at the dot. **Offsides** ghost the offending player (can't interact with the puck) until they tag back to the blue line in `ARCADE`; `NHL` instead runs true delayed offside (tracked but not ghosted — a whistle only fires if the offending team touches the puck, or makes physical contact with a defender, before tagging up — the latter stands in for the real rule's "forces the puck carrier back" / "about to make contact" linesman judgment calls with one deterministic trigger: any contact between the two teams while the delay is active). Both rulesets void it two ways, matching the real rule: the puck fully clearing the attacking zone, or the **defending team establishing possession** (PossessionTracker's ESTABLISHED standard — held it or made a deliberate play, the same "control" bar stat attribution already uses, not a bare touch) while the puck is still in the zone — either way the previously-offside player becomes fully onside without needing to physically tag up. `ARCADE`'s instant ghost is meant to emulate this same underlying rule, it just never produces a stoppage, so it voids on the same conditions NHL does. **Icing** (NHL ruleset only) is a whistle-and-faceoff rule — hybrid-icing race, then a faceoff in the offending team's end; it does **not** ghost the team (the default `ARCADE`/`OFF` sets don't detect icing at all). **Goalie covers** split the same way: `NHL` whistles a defensive-zone faceoff when the goalie smothers a loose puck; `ARCADE`/`OFF` keep play rolling via the goalie's short hold-and-release (see the goalie section). **Crease camping** (dwell-timer ghost, `CREASE_DWELL_DURATION`) is an `ARCADE`-only anti-cheese mechanic, not a real NHL rule — real goaltender interference is contact-based and screening without contact is legal, so it's dropped from `NHL` until a real contact-based interference system exists. Goals trigger a short pause + celebration window. Between periods a fixed 20 s intermission shows the score band + countdown, with the ended period's goals looping behind it when there are any (unanimous Space vote skips the break, like the goal replay), and the post-game screen reveals **Three Stars** over the full-match highlight loop. The default ruleset is `ARCADE` — offsides on, icing off by default — because strict sim rules get in the way of the fast, casual flow.

**Smart ping (G, rebindable) — one context-sensitive team message.** One key, no menu: what the cursor is on, crossed with the possession state, picks the call-out (`PingRules.resolve`, a pure GUT-tested decision table): self → *"Pass to me!"* / *"I'm open!"*; the carrying teammate → *"Shoot!"*; an off-puck teammate → *"Get the puck!"* / *"Get open!"* / *"Pick him up!"* by who possesses; the opposing carrier → *"Get him!"*; an off-puck opponent → *"Cover him!"*; the loose puck → *"Get the puck!"*; bare ice → *"Over there!"*. Display is **team-only** (a ping never telegraphs to opponents): a chat bubble above the pinger's head (`SkaterHUDCoordinator.show_ping_bubble`), except the location ping which drops a pulsing ring + floating text at the spot (`PingMarker`). **Bots obey**: the host routes each ping into the pinger's `TeamBrain` as a bounded directive (`AIPingDirectives`, ~3–6 s expiry, one live order per pinger) that rides the existing role architecture rather than bypassing it — pass/shoot pings are EV **biases** in the carrier's compete (×3, so any remotely reasonable read wins but a hopeless order is still vetoed — never a forced giveaway), cover/pressure/get-open pings force-slot the obeying bot (MARK with a pinned man / PRESSURE / FINISHER), retrieval pings override the chase election, and location pings commandeer steering only. A directed ping at a bot orders *that* bot; at a human it's just the bubble. Cooldown ~1.5 s/player, enforced client- and host-side. Wire: one vote-shaped reliable RPC pair (`request_smart_ping` / `notify_smart_ping`), self-fired locally so offline free play works identically.

**Tone is casual and responsive with a competitive ceiling.** The physics are responsive and forgiving on the surface, but blade placement, shot timing, charge management, and positioning meaningfully separate skilled play. Pick-up-and-play, hard to master.
