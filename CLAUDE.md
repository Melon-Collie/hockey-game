# CLAUDE.md

Context for Claude about the Mitts project. Deep technical reference (networking invariants, class-boundary detail, backlog) lives in `ARCHITECTURE.md`.

## Workflow

Complex features (AI state machines, new systems, architectural changes) can be designed first in Claude.ai chat mode, where the developer can iterate on ideas without implementation pressure. The resulting plan is then handed to Claude Code to implement against the actual codebase. When a session starts with a plan document, treat it as the agreed design — ask clarifying questions before deviating from it.

**Never push to `main` without the user testing locally first.** Feature branches (e.g. `claude/*`) may be pushed after committing so the user can pull and test on their machine. Merging a feature branch into `main` is done by the user via a pull request in the UI — do not `git merge` a feature branch into `main` directly. For work done directly on `main`, always stop at commit and wait for explicit confirmation before running `git push`.

**Scene files (`.tscn`) and complex resource files (`.tres`) are edited by the user, not Claude.** Godot's text formats are error-prone to edit when they contain node unique IDs, sub-resource references, or property ordering that the editor enforces — multi-node scenes, themes, shader materials, animations, etc. Describe the change and let the user make it in the Godot editor. **Trivial single-resource `.tres` files (e.g. `PhysicsMaterial`, simple `StandardMaterial3D`) are safe to author directly** — they're 3-5 lines with no cross-references. The UID line is optional; Godot generates one on first import if omitted.

**You can run the GUT test suite headless; you cannot run the game.** Use the `.claude/hooks/run-gut.sh` runner (it invokes `godot --headless -s res://addons/gut/gut_cmdln.gd`, honoring `.gutconfig.json`). Pass `gut_cmdln` flags through, e.g. `-gdir=res://tests/unit/state`.
- **Local:** `GODOT_BIN` (set in `.claude/settings.local.json`) points at the Godot executable. Full suite ≈ 15–18s. **Redirect to a file, don't pipe** — the Windows console exe throttles badly on an MSYS pipe (≈90s vs ≈18s): `bash .claude/hooks/run-gut.sh > "$TMP/gut.log" 2>&1; tail -40 "$TMP/gut.log"`.
- **Web (Claude Code on the web):** the `SessionStart` hook (`session-start.sh`) async-installs Godot; run `.claude/hooks/wait-for-godot.sh` once before the first test run, then `.claude/hooks/run-gut.sh` (piping is fine on Linux).

Run the suite after touching domain code and report results. The **game itself** still can't run here (needs a display / interactive session) — for gameplay or networking changes, describe what to test in a local session and wait for the user to verify.

**Warnings: run gdlint before committing `.gd` changes.** `.claude/hooks/run-lint.sh` runs `gdtoolkit`'s gdlint (tuned via `.gdlintrc`) — the headless, cross-environment subset of warnings: dead code, unused args/vars, `duplicated-load`, trailing whitespace. A committed `.githooks/pre-commit` gate (activated via `core.hooksPath`, set locally and by the SessionStart hook) **blocks any commit with gdlint problems in staged `.gd` files** (`--no-verify` to bypass). Keep the tree gdlint-clean. Caveat: gdlint can't see Godot's *engine-specific* analyzer warnings (`SHADOWED_VARIABLE_BASE_CLASS`, `INT_AS_ENUM`, narrowing) — those remain editor-only, so a clean gdlint run isn't a guarantee the editor is warning-free.

**If you spot a bug or code smell while working on something else, flag it.** Don't silently fix it (out of scope), don't silently ignore it (it'll rot), don't tack it onto the current commit (muddies the diff). Surface it in chat with a one-line description and let the user decide: fix now as a small follow-up, defer to a separate task, or capture as a Known Issue here. Latent bugs in adjacent code paths are especially worth flagging — they often pair with whatever you're touching.

**Stale documentation is the exception: fix it on the spot.** When a doc or comment (this file, `ARCHITECTURE.md`, doc-blocks, constant tables) no longer matches the code, correct it as part of whatever you're doing — don't flag it as out of scope, don't ask. Keeping documentation and comments truthful is always in scope; a stale doc found while working nearby goes into the same commit.

## What This Is

A 3v3 hockey game built in Godot 4.6.2 (GDScript, 3D). Online multiplayer — one player per machine, each with their own camera and local simulation. Prioritizes feel over realism: deep stickhandling, multiple shot types, satisfying puck physics.

**Puck RigidBody3D has Continuous CD enabled.** Do not suggest enabling CCD as a fix for puck tunnelling — it is already on. Puck escaping the rink is more likely a velocity/reflection compounding bug or a Jolt edge case.

## How It Plays

**Mouse + keyboard only, no gamepad.** WASD skates, mouse cursor places the blade in real-time (continuous IK — the blade chases the cursor every frame, no aim button). Camera is third-person, per-player, dynamic-zoom, tilted ~75° so cursor-to-world projection stays usable for stickhandling.

**Stickhandling is physical, not abstract.** The puck is a real `RigidBody3D` that attaches to the blade by proximity; there is no possession flag you press to engage. Carrying slows you. Moving the cursor swings the blade through forehand/backhand with a small lift through center — that's the "dangling" texture. Hard incoming pucks (above `deflect_min_speed`, 22 m/s **receiver-relative**) deflect off a poorly-angled blade; passes (snap ~14, AI arrival target ~21.5 m/s, soft-sweep wristers down to ~10) catch at any angle for a static or retreating receiver. Reception is purely reactive — it reads the puck's speed **in the receiver's frame** (puck velocity − skater velocity) and the blade angle at contact, nothing else — so a stretch pass to a streaking receiver arrives soft (easy catch), charging head-on into the same feed steepens it past catchable, and skating backward with a hard shot cushions it under the ceiling ("give with the puck" as a *skating* read). Squaring the blade to the relative incoming line is what lets you corral a harder shot (the `alignment_receive_bonus` ceiling, 30 m/s relative); there is deliberately no blade-velocity cushion term (it rewarded a preemptive backswing that felt fiddly — the frame correction rewards positioning, not stick wind-up). The 22/30 thresholds are calibrated to real reception — pros routinely handle ~45–50 mph feeds and treat ~60+ mph as a knock-down even squared; force math + sources on `PuckReceptionRules.should_receive`. Above that ceiling the contact is a **deflect**, and the deflect physics itself produces the whole spectrum from a **bobble** (you knocked it down, it dies in front — a squared blade smothering a hard shot) to a **live redirect** (a glancing blade tips the puck off its line at near-full pace — the deflection-goal geometry). **Hold Q (Deflect) without the puck to deliberately deflect** — a committed "redirect this, don't catch it" that tips even an otherwise-catchable puck off the blade face (angle the blade with the cursor to aim the redirect); release to receive normally. The **loft level (scroll)** picks the deflection *intent* rather than a launch height (a monotonic "higher = launch higher" would rocket a hard tip over the net), and the three levels are symmetric about the ice: **FLAT** keeps a grounded puck low (redirect along the ice); **LOW** takes a grounded puck **up** (the money tip — lift a low shot up and in); **HIGH** takes an airborne puck **down**, batting it to the ice — and the raised HIGH blade is what hooks under an opponent's shaft, so **stick-lift is the same gesture** (hold Q at HIGH near a carrier's stick). Reach follows the blade plane (FLAT/LOW play the ice, HIGH plays the air — an airborne puck flies over a FLAT/LOW blade, a grounded puck passes under a HIGH one), so the only airborne redirect is HIGH's knock-down; the level changes the redirect *direction*, not which plane it reaches. Deliberate and natural deflects run the *same* physics (`PuckCollisionRules.deflect_velocity`), so they always feel identical — one **normal/tangential decomposition** of the incoming velocity against the blade face (the into-face component rebounds with a speed-dependent restitution so hard pucks die head-on; the along-face glance is kept, so a tip holds its pace), with bobble/redirect emerging from blade angle alone and the loft level signing the redirect (flat / up / down). Tunables (`deflect_*`, `bobble_*`) live on `Puck` (detail in ARCHITECTURE → Puck Interactions). AI bots don't use deliberate deflect or voluntary lift (they reuse the held shoot button off-puck for wrister one-timers); Q off-puck for a human is deflect, tapped-on-puck it's still the nudge. No `deke` button — deception is blade placement plus skating rhythm.

**Three shot inputs, all aim-aware:**
- **Quick shot / pass** (E, rebindable) — fires *instantly* from carry (no aim state), a fixed-power player→blade snap toward the cursor. This is also the pass. It's on its own button so there's no tap-vs-hold guess: originally the quick shot and wrister shared LMB and were split by a ~60 ms hold-time cutoff, but an ordinary tap that lingered a few ticks fired a wrister when the player wanted a snap. AI bots fire it via the `quick_shot_pressed` input flag (their uncharged pass).
- **Wrister** (LMB) — always a charged wrister now: hold-and-drag, and the drag direction *is* the aim vector; releasing releases the shot. Power is the **pure mouse-speed model** (`ShotMechanics.wrister_power_t`): the raw screen-space cursor speed at release — scaled by the player's **Shot Power Sensitivity** so it's DPI-independent — is the *whole* power signal; distance dragged does not enter. A slow deliberate sweep is a genuinely soft touch pass (floor ~10 m/s); a hard flick rips the ~33 m/s, Shot-scaled ceiling, with a feel-curve exponent (`wrister_power_curve`) shaping where an ordinary flick lands. `shot_charge` carries *normalized release-now power* every tick — the predicted release the goalie leans on and the stick-flex pose reads; there is no on-screen charge readout for the wrister (the old charge ring was unreadable at flick speed and was removed). Tunables (`wrister_mouse_speed_full`, `wrister_mouse_speed_smoothing`, `wrister_power_curve`) on `SkaterController`; the full-power cursor speed is per-setup (calibrated via Shot Power Sensitivity, replicated online through the join payload), while `wrister_power_curve`'s default is shared with bot gesture synthesis via `GameRules`. Bots have no cursor, so they commit a target power fraction (`InputState.bot_wrister_power_t`) that the controller converts to the equivalent cursor speed via the model's inverse (`wrister_speed_for_power_t`).
- **Slapshot** (RMB) — time-charged wind-up, aim locked at press. Charge feedback is **fully diegetic**: the wind-up animation (blade lift, torso coil, stick rising to `slapper_wind_up_height`) fills over the same `max_slapper_charge_time` as the charge itself — the pose IS the gauge — with a small blade quiver at the apex as the full-charge tell (`slapper_full_quiver_*`); there is no charge ring. Supports **one-timers**: charge without the puck, release fires when the puck enters the shooting zone, at whatever charge was actually built (plus the `one_timer_center_power_bonus` timing bonus) — winding up early is what buys a full-power one-timer.

Backhand shots take a power penalty. Scroll wheel steps a three-level **loft mode** (flat / low / high) that applies to every release in every direction. Each level is a fixed *vertical launch speed*, not a solved arc: LOW is a saucer flip (~0.26 m apex — clears stick blades, lands and slides), HIGH peaks ~1.12 m (puck top ~1.14 m — a clean ~5 cm under the crossbar's inner edge, so you can snipe the top of the net but not sail it over; apex is a fixed height ceiling, power only moves the apex *distance*). Charge buys pace, loft buys height, and where the arc sits when it reaches the net is emergent from distance + power — that range/charge read is the top-corner skill. Passes are quick-shots — same mechanic, no separate pass system; a LOW quick-shot *is* the saucer pass (loft math in `ShotMechanics.loft_y`; per-level speeds `loft_vertical_speed_*` on `SkaterController`).

**Skating is momentum-driven.** Thrust accelerates, drag-friction decelerates naturally, Space brakes hard (heavy friction, direction-agnostic). Backward and lateral (crossover) movement are slower than forward. Facing lazily tracks the cursor, and auto-freezes during shot aim/charge/block states and when the cursor swings into the unreachable wedge behind the skater. No frame-perfect inputs — reads and positioning matter more than execution precision.

**Sprint (Shift) is a stamina-gated top-speed burst.** Holding sprint while skating raises the speed cap (and bumps thrust to reach it) but *widens the turn radius* (`sprint_turn_multiplier` scales facing turn rate in `SkaterPoseCoordinator.apply_facing`) — committed straight-line speed traded for agility, so it's a read rather than a hold-always button. It drains a stamina pool; carrying the puck drains it faster. Empty the pool and sprint locks out until it regenerates past half. The gauge is a BOTW-style **stamina ring** nested inside the local player's own on-ice color ring (`SkaterHUDCoordinator`, self-only): hidden while full, amber when low, flashing red during the exhaustion lockout. Stamina is a 0..1 pool computed by `stamina_rules.gd` (pure/deterministic so it survives reconcile replay), replicated on `SkaterNetworkState` and snapped from the host at replay start like velocity. Tunables (`sprint_*`, `stamina_regen_per_sec`) live on `SkaterController`. Stamina is **Physical-attributed** on two separate curves: a gentle drain scale (sprint *duration* stays usable at every level) and a steep, asymmetric regen scale (*recovery* — a low-Physical player who gases out is locked out far longer than a high-Physical one). The speed cap sprint scales, `max_speed`, is Speed-attributed.

**Physicality is emergent, not scripted.** Body checks trigger from closing-velocity impulse, not a hit button. Ctrl crouches to shot-block (wider hitbox, reflects shots). Poke-checks are stick-on-stick momentum contests — the blades collide and the puck goes where the blended momentum sends it. **Contested pickups** — two blades reaching the same loose puck (a faceoff draw or a board scramble) — are the same kind of contest: nobody is ever awarded possession, the puck squirts free *biased toward the stronger blade's momentum* (a true 50/50 pops out sideways, the "pinched seed"). One resolution, `PuckCollisionRules.contested_pickup_velocity`, shared by the host's present-time pickup tick and the networked lag-comp claim path, so scrambles feel identical however the contestants are hosted. Blade speed already reflects Hands, so the draw rewards the better dangler emergently — no attribute term.

**A hard check staggers its victim.** Beyond the knockback impulse, absorbing a check inflicts a temporary thrust penalty plus a stamina bite, both scaled by how hard it landed — the m/s transfer impulse, which already folds in attacker Size/Physical and the closing Speed, and victim mass. The math is pure (`Scripts/domain/rules/body_check_rules.gd`): hit strength normalizes to a 0..1 intensity between `stagger_min_impulse` and `stagger_ref_impulse`, and a single value, `stagger_timer` (seconds remaining), encodes **both** the penalty depth and the recovery window — a harder hit sets a longer timer, and the per-tick thrust penalty is proportional to the time left, so it eases back to full thrust on its own. The stamina bite charges only the stagger a hit adds *beyond* the residual (`incremental_stamina_drain`), so a clean hit bites full but grinding someone on the boards bleeds at ~the decay rate instead of emptying the pool tick-by-tick. The debuff is host-authoritative (victim-only `Skater.body_check_received` signal — distinct from the both-roles `body_check_impulse_applied`, so a delivered hit's restitution bounce never self-staggers the attacker) and replicated as `stagger_timer`, snapped and re-derived through reconcile exactly like stamina. Tunables (`stagger_*`) live on `SkaterController`; flat for all players in v1 (the hit strength already reflects the combatants' attributes). **Check feedback scales with hit strength too:** the burst (particle count + velocity) and impact sound (volume + pitch) read the same intensity in `SkaterVFX`, which owns one throttled code path for both — a short cosmetic de-dup window coalesces the per-tick re-fires of `body_checked_player` during sustained contact so one hit reads as one impact. (Genuine head-on collisions still emit from both bodies by design — two impact points.)

**Goalies are AI-only, never player-controlled.** Tuned for *beatable realism* — they should look and move like a real goalie while staying deliberately scorable (the realism additions only ever open scoring windows, never buff a set goalie into a brick wall). Reactive with a small reaction delay (the window for close-range top-corner goals) that a **pre-armed read** shortens when the goalie has been fixated on a visible windup (quiet-eye anticipation — quick-release snaps never prime); positional depth chart on the challenge-angle arc, with a **speed-matched rush backflow** (a closing carrier retreats the goalie along the taught curve at the attacker's pace — decelerating strands him out at challenge depth); butterfly with a commit timer to prevent toggling and a **grounded ~0.2 s drop** (measured pro drop speed, so clean low shots in tight beat a purely reactive drop — sealing early via the proactive triggers is the counter); **squares to the puck, not the shooter's body** (dangle jitter is absorbed by distance-scaled tracking lag — the quiet-eye smoothing — rather than by aiming at the chest). The read degrades exactly when a real goalie's would: **screened** (a body in the puck→goalie sightline delays pickup, and a *fully* screened release flips save selection to a blocking butterfly — drop on the read, eat the top-corner exposure) and **caught moving / unset** (mid-push, sliding, or standing up reads the shot late). Lateral pushes **accelerate onto the edge** (`lateral_accel`) rather than snapping to speed, so quick cross-ice plays beat the goalie across; when the cross-crease race is *already lost* the goalie goes **pads-first** (drop-and-slide toward the crossing) instead of arriving late upright. Two anticipatory reads guard the back door: a live **weak-side one-timer man caps the challenge depth** (`backdoor_depth_cap` — a pass-flight vs. re-square race, so respecting the back door opens the carrier's direct-shot angle instead), and a lateral drive that **wins the race to the post** (`is_beaten_wide` — keyed on the *puck*, not the body: a forehand-drag drive with the puck trailing commits nothing until the puck crosses the goalie's sealing reach, the point of no return — and it must be a *sustained* drive — carrier-driven lateral commits hold for a quiet-eye confirmation beat, `lateral_commit_confirm_s`, so a deke's transient spike un-commits when pulled back; pass-driven seals stay instant since a puck in flight can't cut back) drops the goalie into the butterfly-slide post seal rather than an unwinnable standing chase — baiting that committed drop with a fake held past the confirmation is the counter. Post play splits at the goal line: **RVH** seals at/below it (wraps, walkouts, dead angles), **VH** — post pad vertical, body tall — takes the in-front sharp-angle shot threat, closing RVH's short-side-high hole. While down, the goalie **knee-shuffles** (slow sealed micro-scoots toward the arc target) between committed slides — the real three-tier down movement — and the **head tracks the raw puck** in every state (eyes-lead; the body plays the smoothed threat). A committed **stick lunge is a gamble** (fully-unset read while extended). Loose pucks in the crease follow the real cover-vs-clear hierarchy: the corner sweep is **lane-aware** (exit corner picked by opponent reach-vs-flight — `sweep_lane_blocked`; a covered lane flips corners), and when **every lane is covered with an opponent on the puck, the goalie smothers it** (`COVERING` — a glove-race cover that a well-timed whack still beats), and a puck that comes to **rest on the goalie's body** (a deadened save settling on the pad tops — the only body that can support a puck off the ice) triggers the same smother, since no blade can legally reach it there. The cover resolves by ruleset: `NHL` whistles the play dead and faces off in the defensive zone; `ARCADE`/`OFF` run a flow-preserving **hold-and-release** (~0.85 s of dead puck that kills the scramble and lets the defense reset, then the goalie plays it out himself through the same lane-aware sweep — no stoppage, the same philosophy as the offside ghost), spaced by a cover cooldown. Bots treat the covered puck as dead (the loose-puck chase election returns nobody while it's locked), so they reset to their slots instead of crowding the smother. The goalie also **plays rims behind the net** — tier-1 conservative only ("stop it, leave it, get back"): a paddle-down trap at the boards directly behind the cage, gated by an ultra-conservative go/no-go race (full-sprint forechecker assumption, whole-trip clock, fat margin, net-front lurker veto) and re-checked every tick with a stricter abort margin so he visibly bails early rather than ever getting caught out; he never carries or passes (the misplay-prone tiers of real puck handling are deliberately absent), the trip routes around the post via a waypoint — skated with a real stride (a procedural gait borrowed from the skater's stroke warp, distance-driven so it freezes when he stops; PLAYING_PUCK only, the crease glide is correct goaltending) — and only the HARD tier plays the puck at all (`GoalieSkillProfile.puck_play_go_margin_s` is INF below it). Saves follow real rebound doctrine: the chest **absorbs dead**, the glove **catches and holds** (squeeze-and-look — a catch under pressure freezes the play through the same rails as the smother, NHL whistle / ARCADE hold; an unpressured catch look-and-drops after a beat and plays on, the real delay-of-game incentive), controlled pad/blocker saves are **steered cornerward at pace** (modern active rebounds — `GoalieSaveRules`), hard shots beat the pad and kick a live rebound; angled pads (pose toe-out + pad material, not a physics override) keep deflections out of the slot. Pure read/positioning/rebound math lives in `Scripts/domain/rules/goalie_behavior_rules.gd`; tuning is `@export`s on `Scripts/controllers/goalie_controller.gd`.

**Game format:** 3v3, three periods plus optional OT, period length tunable. Faceoffs have a short "2 → 1 → DROP" prep; the drop is a **live** puck (no possession assignment), so winning the draw is a real contested pickup — see *Physicality* above — decided by which center's blade wins the momentum contest at the dot. **Offsides** ghost the offending player (can't interact with the puck) until they tag back to the blue line in `ARCADE`; `NHL` instead runs true delayed offside (tracked but not ghosted — a whistle only fires if the offending team touches the puck, or makes physical contact with a defender, before tagging up — the latter stands in for the real rule's "forces the puck carrier back" / "about to make contact" linesman judgment calls with one deterministic trigger: any contact between the two teams while the delay is active). Both rulesets void it two ways, matching the real rule: the puck fully clearing the attacking zone, or the **defending team establishing possession** (PossessionTracker's ESTABLISHED standard — held it or made a deliberate play, the same "control" bar stat attribution already uses, not a bare touch) while the puck is still in the zone — either way the previously-offside player becomes fully onside without needing to physically tag up. `ARCADE`'s instant ghost is meant to emulate this same underlying rule, it just never produces a stoppage, so it voids on the same conditions NHL does. **Icing** (NHL ruleset only) is a whistle-and-faceoff rule — hybrid-icing race, then a faceoff in the offending team's end; it does **not** ghost the team (the default `ARCADE`/`OFF` sets don't detect icing at all). **Goalie covers** split the same way: `NHL` whistles a defensive-zone faceoff when the goalie smothers a loose puck; `ARCADE`/`OFF` keep play rolling via the goalie's short hold-and-release (see the goalie section). **Crease camping** (dwell-timer ghost, `CREASE_DWELL_DURATION`) is an `ARCADE`-only anti-cheese mechanic, not a real NHL rule — real goaltender interference is contact-based and screening without contact is legal, so it's dropped from `NHL` until a real contact-based interference system exists. Goals trigger a short pause + celebration window. Between periods the ended period's goals replay behind an intermission score band (the break scales with the reel; unanimous Space vote skips it, like the goal replay), and the post-game screen reveals **Three Stars** over the full-match highlight loop. The default ruleset is `ARCADE` — offsides on, icing off by default — because strict sim rules get in the way of the fast, casual flow.

**Tone is casual and responsive with a competitive ceiling.** The physics are responsive and forgiving on the surface, but blade placement, shot timing, charge management, and positioning meaningfully separate skilled play. Pick-up-and-play, hard to master.

**Where the numbers live** (don't bake these into prose — read them when you need them): movement, shot, and body-check-stagger tuning (`sprint_*`, `stagger_*`) in `Scripts/controllers/skater_controller.gd`; shot math in `Scripts/domain/rules/shot_mechanics.gd`; stagger math in `Scripts/domain/rules/body_check_rules.gd`; period/faceoff/offsides/icing constants and presets in `Scripts/domain/config/game_rules.gd`; goalie tuning in `Scripts/controllers/goalie_controller.gd`; **per-player attribute multipliers** (Speed/Agility/Hands/Size/Physical/Shot → gameplay + visual effects) in `Scripts/domain/state/player_attributes.gd`.

## Player Attributes

Each skater has six attributes — **Speed, Agility, Hands, Size, Physical, Shot** — on a 5-step scale (1=floor … 3=medium/baseline … 5=ceiling). The picker UX is *point-buy*: one 1–5 slider per attribute in the side menu's player popup, with the total spend bounded by `PlayerAttributes.BUDGET` (18). All-medium sums to 18, so an all-medium all-rounder is legal but unspectacular — any spike to 5 forces a dip to 1 somewhere (the picker requires exact-budget spend to Apply). The 5-step tables keep the old 3-step endpoints (old level 3 == new level 5), so widening the scale changed granularity, not range. Bots have curated picks in `data/bot_identities.json` (each summing to budget). Online matches lock attributes at join time (replicated as six int levels through `request_join` / `spawn_remote_skater` — `PROTOCOL_VERSION` bumped for the wider payload — validated host-side by `is_within_budget` with `<=` so fresh/migrated under-budget builds aren't reset); free-play picks re-apply immediately to the live skater without a respawn.

What each drives (headline effects):
- **Speed** → `max_speed` (top end; also feeds sprint payoff, since sprint multiplies `max_speed`) *(+ visual thigh bulk)*
- **Agility** → `thrust` (all-direction acceleration), turn rate, brake power, edge glide (`friction_drag` inverted) *(+ visual calf bulk)*
- **Hands** → `max_blade_speed` (the dangle/pass-absorb "hands" lever — the cap is now low enough to actually bind, so it gates fast-dangle speed; capped *relative to the skater* so skating velocity doesn't eat the budget), `puck_carry_speed_multiplier` (carry speed — how little the puck slows you, ±10%), and the **backhand power coefficient** (`hands_backhand_mult` un-penalizes the backhand toward 1.0 — the in-tight finish; wrister-only, there's no backhand slapper) *(+ visual forearm bulk)*
- **Size** → weight (±18% spread, ~1.44× heaviest-to-lightest), hitbox cylinder, arm length / ROM (height 5'7"/5'10"/6'0"/6'3"/6'5" by level on the 1.78 m mesh — a tall, modern-NHL-skewed league; note the height/stick/charge multipliers put their 1.0 identity at L2, since medium-Size is 6'0"), **stick length on a gentler curve** (`stick_len_mult`, ~0.65× the height deviation — the stick is equipment, not anatomy, so small players keep near-full-size sticks; total blade reach is still arm-driven ROM + stick). Resists checks through **mass** (the weight_ratio in `skater.gd`) — a big player is hard to *move* *(+ visual height, torso/head bulk)*
- **Physical** → `body_check_transfer` (how hard you DELIVER a hit — the **widest canonical spread, ±36%**, so a maxed enforcer hits like a freight train and a low-Physical player barely registers a check, falling under the stagger threshold at moderate speed). The same delivered-impulse magnitude also gates **whether a hit knocks the puck off the carrier** (`BodyCheckRules.puck_strip_impulse`, reconstructed from the collision impact and fed to `Puck.on_body_check`), so a low-Physical shove staggers *and* strips less than an enforcer's. Physical also drives `body_check_brace_resistance` (hard to PUT DOWN — the active brace, inverted), and stamina (gentle drain/duration curve + steep low-end regen/recovery curve). Body checks read **two axes that compose, not double-count**: Size sets `weight` (mass; hard to move and hits hard by sheer momentum), Physical sets the transfer/brace coefficients (delivery + hard to put down) — Physical is the stat that says "I hit people," Size the one that says "I can't be moved." The grinder / motor stat *(+ visual shoulder/yoke bulk)*
- **Shot** → the **charged-shot power ceiling** (`shot_power_mult` on wrister max + both slapper pools, ±18%, **anchored to real NHL speeds**: L5 is an elite release — ~87 mph wrister / ~106 mph slapper — L3 league-average, L1 weak-for-pro; anchors documented on `_SHOT_POWER_MULTS` and the `GameRules` base maxes) and the **slapper wind-up time** (`shot_charge_mult`, inverted — high Shot threatens sooner). The quick/uncharged snap stays **baseline** for everyone because it doubles as pass speed, so Shot is "what a charge buys you," not snap power. (The wrister has no charge-effort lever anymore — power is pure cursor speed, so how fast you fill the ring is your hand, not the stat.) *(+ visual upper-arm bulk)*

All tuning multipliers live as private constants on `PlayerAttributes`, read via named accessors (`attrs.speed_mult()`, etc.) — **never index a `_*_MULTS` table outside that file**. Several attributes drive *multiple* tables with different spreads (Shot: charged ceiling + slapper wind-up; Physical: stamina drain + regen; Hands: blade / carry / backhand). Visual scaling decouples from gameplay magnitudes (arm bulk runs ±40% asymmetric; each attribute's visual tell is tagged in the list above). To add a new "X scales Y" rule, see the doc-block at the top of `player_attributes.gd`.

Application path: `SkaterController.apply_attributes(attrs)` reads the canonical fields and writes scaled values to controller `@export`s, `Skater.weight`, etc.; `SkaterAppearanceCoordinator.apply(attrs)` does the visual mesh scaling. Both are idempotent — they capture baseline values on first call and recompute from baselines on every subsequent call, so repeated applies (from free-play picker changes) never compound. **Prefs migration** (`player_prefs.gd`, gated by `attr_scale_version`): legacy 1–3 saves remap to the 1–5 scale (`new = 2·old − 1`) and the Strength→Skill rename; then the four-attribute scale splits into six (version 3) — old Skill becomes **Shot**, **Hands** and **Physical** seed at medium and are trimmed (Hands first) to fit `BUDGET` without disturbing the player's expressed identity.

## Layer Architecture

The codebase is split into three layers; dependencies always flow downward:

- **Domain** (`Scripts/domain/`) — pure GDScript, no engine APIs. Rule classes (static methods), the game state machine (RefCounted), enums, and game-rule constants. Fully unit-testable without Godot.
- **Application** — `GameManager` (autoload orchestrator), controllers, `ActorSpawner`, and six RefCounted collaborators. Use the domain to make decisions; reach into infrastructure to execute them.
- **Infrastructure** — actor nodes (Skater, Puck, Goalie), `NetworkManager`, UI. The Godot-side glue.

Lower layers never reach up: actors take their collaborators via `setup()` (e.g. `Puck.set_team_resolver(Callable)`); controllers take a `game_state: Node` exposing `is_host()` / `is_movement_locked()`). Upward communication is by signals that the orchestrator listens to.

See `ARCHITECTURE.md` → **Confusing Boundaries** for class-responsibility detail (`GameStateMachine` vs `PhaseCoordinator` vs `GameManager`, `constants.gd` vs `game_rules.gd`, `SkaterController`'s five `RefCounted` collaborators, etc.).

## Autoloads

Initialized in this order: `PlayerPrefs` → `Constants` → `BuildInfo` → `SoundManager` (`sound_manager.gd`, no class_name) → `NetworkManager` → `NetworkSimManager` (`network_sim.gd`, no class_name) → `SteamManager` (`steam_manager.gd`, no class_name) → `GameManager`. `NetworkManager._ready()` is a no-op; the menu drives initialization. `SteamManager` owns every GodotSteam (`Steam` singleton) call — init + lobby lifecycle — and degrades to a no-op (`is_available = false`) when Steam isn't running or the GDExtension is absent (headless CI), so offline/free-play/tutorial and the GUT suite are unaffected. `SoundManager` exposes `play_ui` and `play_world` (sound constants in its `Sound` enum).

## Code Conventions

**Strong typing everywhere.** Typed arrays (`Array[BufferedPuckState]`), typed function signatures, typed variables. Never leave a type annotation off when it can be provided. Prefer `var state: PuckNetworkState` over `var state`.

**Cast or annotate when chaining through superclass APIs.** GDScript's type inference can't see through methods that return a base class — e.g. `Engine.get_main_loop()` returns `MainLoop`, not `SceneTree`, so `var scene := Engine.get_main_loop().current_scene` fails to infer. Same pattern for `find_child()` (returns `Node`, not the subclass), `get_node()`, `instance_from_id()`, etc. Add an explicit type (`var scene: Node = ...`) or a cast (`as SceneTree`, `as Node3D`) so the analyzer can resolve member access on the next line. The fix is mechanical; don't ship inferred-from-superclass typing.

**Godot naming conventions.** `snake_case` for variables and functions, `PascalCase` for class names, `SCREAMING_SNAKE_CASE` for constants.

**Separation of concerns.** Physics bodies (`Puck`, `Skater`) expose a clean API. Controllers drive them. `GameManager` owns spawning and world state. `NetworkManager` owns RPCs. Don't reach across these boundaries casually.

**Network API uses typed objects, not raw arrays.** Functions accept `SkaterNetworkState` / `PuckNetworkState` directly. Serialization happens only at the RPC boundary.

**Get it working, then tune numbers.** Use `@export` on tunable parameters so values can be adjusted in the editor. Don't prematurely optimize or bikeshed on constants before the mechanic runs. **Live editor tuning is not a workflow here** — the developer doesn't tweak exports while the game runs, so hot-path code may cache config objects built from exports (rebuilt on `apply_attributes`) without preserving per-tick rebuild semantics. Don't undo config caching to restore live-tuning.

**Grounded models over magic-number curves — in evaluation code especially.** When code *evaluates* a situation — the bot AI's utility scoring, the goalie's read, any "how dangerous / open / safe is this?" number — build the result from a model of quantities the actor can physically "see," not a curve shaped to feel right. Every multiplier should read as real data: the open-net angle a shooter can hit, a defender's reach vs. the puck's flight time, the goal mouth's projected width — not `1 − x/K`. The payoff is leverage — a grounded model generalizes to cases you never tuned and stays honest when an upstream number moves — so it's worth more up front than a curve. When a behavior is wrong, fix the *model* (give it the perception it's missing); don't bolt on a corrective hack or a hard positional gate, which only compensates for a model that isn't seeing something and then rots. A magic curve in an evaluator is a model you haven't built yet. This is **not** a ban on hand-set numbers: *feel / tactical* tunables — `stagger_*`, staging offsets, loft heights, difficulty knobs, how the game should *play* — are legitimately chosen by hand. The line is evaluation vs. feel; when you must add a constant to an evaluator, make it a physical measurement (a reaction delay, a reach, a body width), not a shape parameter. See `ARCHITECTURE.md` → **Bot AI** for how the scoring models embody this.

**Hot-path discipline — the 120 Hz tick multiplies every cost.** Anything reached from `_physics_process` or a per-tick controller `update()` runs 120×/second × actor count (6 skaters + 2 goalies + puck), and reconcile replay re-runs the per-tick body once *per replayed input* — so a hot-path cost is amplified again exactly when the network is bad. The host's per-tick budget is shared: when it overruns, physics dilates against the wall clock, and because the broadcast cadence is counted in physics ticks (`network_manager.gd` `_state_tick_divisor`), *every client's* update rate sags with it. A single host-side hot-path regression degrades the whole lobby. Two failure modes, in order of impact: **(1) Allocation churn** — short-lived heap objects per tick: `.new()`, Dictionary/Array literals, `.filter()`/`.map()`/lambdas, `x in [literal]`, returning a fresh `Dictionary`/`Array`, per-call `String` formatting — pressures GDScript's allocator/refcount on the main thread; this is the dominant cost (audit P1–P5). Value types (`Vector3`, `Basis`, `Transform3D`) do **not** heap-allocate, so the math is cheap — the enemy is the heap object, not the arithmetic. **(2) Unnecessary cosmetic work** — visual-only updates (mesh/arm IK, `look_at`, decals) that don't feed gameplay belong in `_process` (render rate), not `_physics_process`, and should skip when idle (dirty-flag) or off-screen (visibility cull); gameplay reads the `blade`/`Marker3D` anchors, not the cosmetic mesh, so cosmetic IK at tick rate is pure waste (audit P2, P8). **Keep the layer boundary AND the performance — they don't conflict:** a Callable/collaborator boundary is an interface, not a license to allocate per call. *Memoize at the seam* — cache the result and invalidate on change (`PlayerRegistry` caches `Array[Skater]`; `puck_controller` caches `team_id_by_skater`). *Build once, fill scratch* — configs that only change on `apply_attributes` are built there and reused; solvers fill a caller-owned result instead of returning a fresh `Dictionary` (`GoalieBodyConfigBuilder`'s shared scratch config is the model). Before adding per-tick code, ask: does it run at 120 Hz × actors? does it allocate? is it cosmetic (→ `_process` + dirty/visibility guard)? Spot a hot-path allocation while working nearby — flag it per the bug-flagging rule; the standing backlog lives in `ARCHITECTURE.md` → Known Issues / Planned Work. This is not in tension with "get it working, then tune numbers" above — that's about *constants/feel*; this is about *structure*, and structure is cheaper to get right up front than to retrofit.

**Don't shy away from complexity when it improves feel.** This project already has full client-side prediction with input replay, buffered interpolation, and puck trajectory prediction with reconciliation. If adding a complex system will make the game feel meaningfully better to play, it's worth doing — think it through carefully first, then implement it properly.

**All popups and modal dialogs must be closeable via `ui_cancel` (Escape).** Add the popup to the existing `_unhandled_input` block in the relevant UI script — check `popup.visible`, hide it, and call `get_viewport().set_input_as_handled()`.

## Launch Modes

All start paths go through `Boot.tscn` (title card): `boot.gd` threaded-loads `Hockey.tscn`, then drops the player into free play via `NetworkManager.start_free_play()` (first launch routes into the Basics tutorial via `start_tutorial()` instead). From there the HUD's `SideMenu` drives session changes — `start_offline()`, `start_host()`, or `start_client_lobby(lobby_id)`. `NetworkManager._ready()` does nothing. Online transport is **Steam P2P via `SteamMultiplayerPeer`** (GodotSteam GDExtension), a drop-in `MultiplayerPeer`, so all RPCs/prediction/reconcile/lag-comp are transport-agnostic and unchanged. Unlike ENet's instant `create_server`/`create_client`, Steam lobby create/join are **async**: `start_host()` waits for `SteamManager.lobby_created` then emits `host_lobby_ready` (the menu spinner waits on it before changing scene); `start_client_lobby()` waits for `lobby_joined`, reads the lobby owner's Steam ID, then the normal `connected_to_server` handshake runs unchanged. `Hockey.tscn`'s root node runs `game_scene.gd`, whose `_ready()` calls `NetworkManager.on_game_scene_ready()`, which emits `host_ready` on hosts; `GameManager` listens and calls `on_host_started`. Client world spawn is triggered by the `client_connected` signal from `_on_connected_to_server()`.

NetworkManager → GameManager communication is signal-based: every RPC / ENet callback emits a typed signal, and GameManager wires all connections once in `_ready()` via `_wire_network_signals()`. The only downward data flow is `NetworkManager.set_world_state_provider(Callable)`.

## Distribution

Playtester builds ship via GitHub Releases (`latest` tag). `deploy.yml` computes `VERSION=0.1.<git rev-list --count HEAD>`, rewrites the placeholder `"dev"` in `Scripts/game/build_info.gd` to that string before export, and publishes with the version as the release name (plus an immutable `v0.1.N` prerelease per build for rollback). Steam (SteamPipe) now handles distribution and auto-updates for the closed beta (`steam/` holds the upload scripts); the old GitHub-release `UpdateChecker` startup notifier has been removed since Steam owns updates. No in-game patching/downloader.

**Supabase backend:** `Scripts/game/supabase_config.gd` holds the project URL and publishable (anon) key — safe to commit, RLS restricts it to INSERT/SELECT/UPDATE. `CareerStatsReporter` (`Scripts/game/career_stats_reporter.gd`) POSTs one row to `career_stats` at game-over and GETs from the `career_totals` view for the career screen. `BugReporter` (`Scripts/game/bug_reporter.gd`) POSTs to `bug_reports` with a telemetry snapshot. `NetworkSessionReporter` (`Scripts/game/network_session_reporter.gd`) POSTs one connection-quality row per online game to `network_sessions` at game-over — the playtesting telemetry pipeline (see `ARCHITECTURE.md` → **Playtesting telemetry**; schema + analysis view in `sql/network_sessions.sql`). All use fire-and-forget `HTTPRequest` nodes added to the scene tree root and fail silently. The secret key must never be committed — use only the publishable key in `SupabaseConfig`. **Table/view/RPC schemas are version-controlled in `sql/`** (one file per feature; `sql/dump_schema.sql` regenerates them from a live DB). All backend rows key on `steam_id` — there is no per-player `uuid` (`game_id` is still a UUID, minted by `PlayerPrefs.generate_uuid`).
